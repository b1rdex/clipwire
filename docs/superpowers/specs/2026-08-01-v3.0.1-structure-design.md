# clipwire v3.0.1 — structure, without touching behaviour

**Date:** 2026-08-01
**Status:** batya-approved
**Amends:** nothing on the wire. This release changes no protocol, no format and no
observable behaviour. It exists to make the next release safe to write.

## Why this exists

Three files grew past the point where a reviewer can hold them:

| file | lines |
|---|---|
| `agent/tests/test_watcher.py` | 3703 |
| `agent/clipwire-agent.py` | 3221 (of which `class Agent` is 1251) |
| `Tests/clipwireTests/HandleFrameTests.swift` | 1855 |
| `Sources/clipwire/main.swift` | 1284 |

Size alone would not justify a release. What justifies it is the project's own defect
record: **three of the defects that reached production lived *between* two changes that were
each correct and each independently reviewed.** That failure mode gets likelier as the
distance between related code grows, and it is the one this project keeps paying for.

## The criterion, decided first, because it constrains everything else

A refactor's whole claim is that nothing changed. The only evidence that carries weight:

> **The test suites pass unchanged, and `git diff` of every test file and every golden
> fixture across the entire branch is empty.**

One command, checked at branch review:

```sh
git diff --stat main...HEAD -- Tests/ agent/tests/ fixtures/
```

"Not in the same commit" was the first draft of this rule and it is too weak — an adjustment
simply moves to a neighbouring commit. The diff is over the whole branch or it is worthless.

**One carve-out, and exactly one, because the rule as first written forbade its own
enforcement.** Part 1 adds a check that the file's sections stay in their declared order —
and adding a test is a change under `agent/tests/`. The rule is therefore: *no existing test
or fixture may change by a single byte*, and the diff may contain **one added file**,
containing **only** the section-order check. So the command above must print exactly one
line, naming that file, and every other path must be absent. A modification to any existing
test file fails the release outright.

**And that file reads the agent as text, never imports it.** The check is a regex over the
section headers, so it cannot execute a line of agent code and therefore cannot mask a
behaviour change even in principle. That makes the carve-out orthogonal by construction
rather than by assurance — and it keeps the check independent of whether the agent's runtime
imports resolve at all.

That the first draft of the criterion outlawed the work it was written to protect is worth
leaving visible: it is the same shape as the acceptance clause v3 had to retire, where a
rule outlived the premise it was built on.

**Necessary but not sufficient.** The suites drive each side against scripted pipes; there is
still no loop test, because the transport override recommended after v2 was deliberately not
built. What lives only in the loop — initialisation order, startup timing, the sequence in
which threads come up — is exactly what a restructuring can break while every test stays
green. So the bar is the empty diff **plus a five-minute live smoke after merge**: connect,
a clip each way, a reconnect. Written into acceptance below.

## Part 1 — Python: do not split the file

`install` performs **one** `scp` of `agent/clipwire-agent.py`, sets the executable bit and
runs `--selftest`; `run` executes that path directly over ssh (`main.swift:1233-1273`). The
single file is the delivery mechanism, not a style choice.

Four options were weighed. **The decisive argument is not about delivery at all: options
B, C and D are incompatible with the criterion above.** The tests import one module. A
package, a build-time concatenation and a zipapp each change either the import or the shape
of the artifact, so the suites *cannot* pass unchanged. The purity criterion would die
together with the split, and with it the only evidence that the refactor was safe.

The delivery objections stand on their own besides:

- **A package delivered with `scp -r`** loses atomicity. A dropped connection today leaves
  either the old agent or the new one; with a directory it can leave a mixture of both.
- **A build step that concatenates modules** inserts a generator between the file a person
  reads and the file that runs on the PC. That is this project's signature defect class in
  a new location.
- **A zipapp** cannot be read on the PC during an incident. Every diagnosis this project has
  made — the whitespace trim, the re-encode, the gdbus leak — began by reading the deployed
  file on the machine it was failing on.

### What replaces the split: a declared order, mechanically enforced

The real risk in 3221 lines is not length, it is drift — related code separating over time
until a reviewer cannot see two halves of one rule at once. So the file declares its own
table of contents in the header, and a test enforces that the sections appear in that order
and that nothing lives outside one.

This composes with `TestModuleDefinitionOrder`, which already pins the one structural rule
the file has (nothing may be defined below `if __name__ == "__main__":`). The new check is
that rule generalised.

Sections, in the order the file already uses — read out of the file, not tidied:

1. Frame codec — constants, `FrameError`, `encode_frame`, `decode_frame`
2. Clip payloads — text and image, `encode_*`/`decode_*`
3. Freshness — decisions, kinds, clip-state codec, `resolve_freshness`
4. Agent runtime — version, phases, logging, skew
5. `class Agent`, and `class NeverReadyClipboard` behind it
6. Clipboard state — XDG paths, the store, startup and current resolution, announcing
7. Wayland clipboard — `choose_kind`, `WaylandClipboard`, subprocess plumbing
8. Selftest — `_select_clipboard`, `selftest`
9. Watchers and entry — GPaste, polling, the safety net, `main`, `if __name__`

**`selftest` sits before the watchers, not after them.** The first draft of this list put an
"Entry" section last, because that is where an entry point usually goes; in this file it is
not. The list must describe the file, since the alternative — moving code so the file matches
a nicer list — is exactly what this release forbids.

### `class Agent` at 1251 lines is deliberately left alone

Breaking it up means composition — new objects, new call paths, new initialisation order.
That is a behaviour-touching change wearing a refactor's clothes, and it cannot be made
under a criterion that forbids touching the tests. It is a separate decision, deferred with
its reasoning recorded rather than by omission.

## Part 2 — Swift: split freely

Delivery is a compiled binary, so none of the Python constraints apply. The criterion is
the same and the tests still may not move. `main.swift` becomes an entry point and nothing
else; every extraction is a whole declaration moved verbatim, with no signature changed.

| new file | moved from `main.swift` | lines |
|---|---|---|
| `Hello.swift` | `ProtocolConstants`, **`private struct HelloPayload`**, `decodeHello`, `SkewConstants`, `skewLogLine` | ~136 |
| `AgentStatus.swift` | `final class AgentStatus` | ~157 |
| `ClipStateAnnouncement.swift` | `sha256Hex`, `resolveCurrentClipState`, `ClipStateAnnouncement`, `persistClipState`, `announceClipState` | ~237 |
| `LocalChange.swift` | `outgoingClipFrame`, `handleLocalChange` | ~101 |
| `HandleFrame.swift` | `handleFrame` | ~431 |
| `Commands.swift` | `runAgent`, `printStatus`, `initConfig`, `install` | ~157 |

`main.swift` keeps `AgentPaths`, `wireAgent` and the argument switch — about 70 lines.

**`handleFrame` at 431 lines is moved, not divided.** Splitting a function is behaviour-
touching for the same reason `class Agent` is; the file boundary is free, the function
boundary is not.

### A move falsifies positional comments, and they get one repair commit

A verbatim move preserves a doc comment that says "the heartbeat timer **below**" — while
moving the timer to another file. The rule that keeps moves honest therefore manufactures
false comments, in exactly the channel this project has measured as the one its audits miss:
seven false comments across v3's fourteen tasks, every survivor a sentence about how things
are arranged rather than a number.

Leaving them and repairing them inside the move each give up an invariant — the first merges
known-false text, the second destroys the only mechanical guarantee that a move contains no
edits. So the two invariants get separate commits with separate checks:

1. **Move commits are permutations**, proved by reconstructing the original file from its
   pieces and diffing byte-for-byte against the pre-move version.
2. **One repair commit**, after all moves, fixing only the bearings the moves themselves
   broke. It must touch no executable line, and that is checked instrumentally rather than by
   reading: **strip comments from both versions and the diff must be empty.**

A reviewer never has to tell a repair from a smuggled edit by eye; the tool does it.

**Repair to a symbol, not to a position.** Replace "below in this file" with the name of the
file or the symbol — `runAgent`, `Commands.swift`. A positional bearing will break again at
the next move; a symbolic one survives. The point is to fix the class, not the instances.

The implementers of each move collect the bearings their own move falsified. **That list is
necessary and provably not sufficient**, because it is blind in one direction: a comment in a
file that *did not move*, naming a symbol that did, is nobody's move to notice. Seven such
bearings survived the first repair pass here — a reader following `ClipStateStore.swift:16`
would open an 84-line `main.swift` looking for a `persistClipState` that is not there.

So the scope is that list **plus a sweep of every unmoved file for references to moved
symbols**, which is mechanical: for each moved declaration, grep the whole target for its name
and read every hit's locative. The sweep closes the blind direction; the movers' lists close
only the near one.

### Visibility is the one thing a move can silently change

Within a single module, moving declarations between files changes nothing observable — with
one exception. `private` in Swift is scoped to the *file*, so a declaration that moves away
from its private dependency stops compiling, and the obvious repair is to widen the modifier.
That repair is a real change hiding inside a move.

`main.swift` has exactly one such declaration: `private struct HelloPayload` (`:34`), used by
`decodeHello` (`:73`). The table above moves them together for that reason.

**The rule, and it is absolute: declarations bound by `private` or `fileprivate` visibility
move together, and no access modifier may be widened.** If widening looks necessary, the file
boundary has been drawn in the wrong place — move the boundary, not the modifier. Grep for
`^(private|fileprivate)` in every file before and after; the two lists must be identical.

## What this release does not do, recorded so the omissions are decisions

- **The test files are not split.** The criterion freezes them, which would freeze them
  forever if left unstated. The sequence is deliberate: this cycle splits production code
  with the tests frozen; **the next cycle splits the tests with production frozen**, under
  the mirror-image criterion — `git diff` of `Sources/` and `agent/clipwire-agent.py` empty.
  Both halves get the same evidence, neither gets it at the same time as the other.

  **That cycle inherits four debts, named here so they arrive as decisions and not
  discoveries.** Each is a test comment this release falsifies and may not touch, because the
  frozen-test rule outranks a stale line in a test:

  - `Tests/clipwireTests/FrameTests.swift:104` — `ProtocolConstants` → `Hello.swift`
  - `Tests/clipwireTests/HandleFrameTests.swift:1621` — "two concatenated string literals
    (main.swift)" → `HandleFrame.swift`
  - `Tests/clipwireTests/HandleFrameTests.swift:1676` — "enumerated on `persistClipState` in
    main.swift" → `ClipStateAnnouncement.swift`
  - `Tests/clipwireTests/LogTests.swift:13` — "main.swift's fatal-config-error path" →
    `runAgent`, in `Commands.swift`

  A list naming one of four would have defeated its own purpose.
- **Retina `pHYs` is not fixed here.** It is a behaviour change and belongs to its own cycle.
  Two things must be in that spec from the first draft, because both were found only by
  attacking the obvious fix:
  - The sketch of "keep the local bytes, adopt only the peer's hash" **breaks the read-back
    invariant.** The store would no longer match what the clipboard returns, so the next
    reconnect's startup seed sees a mismatch, stamps `now`, and logs a false `clipboard
    changed while apart` — precisely the failure v3 closed. It needs a *pair* of hashes in
    the store: canonical for announcing, local for the seed comparison.
  - **The fix can only live on the Mac.** Decompressing a PNG to pixels needs a real decoder,
    which the PC side does not have and cannot reasonably grow, and the PC's clipboard will
    carry no `pHYs` regardless because GPaste re-encodes whatever it is given.

## Acceptance

1. **The diff check passes.** `git diff --stat main...HEAD -- Tests/ agent/tests/ fixtures/`
   names the one added section-order file and nothing else. This is the release's central
   claim; if it fails, the release is wrong, not the check.
2. **Every existing test still passes, and the counts move only by the carve-out.** Swift
   stays at exactly 243 — nothing is added there. Python's 311 existing tests all pass, and
   the count rises by however many the section-order file contributes; **the release report
   names that number.** A Python count of exactly 311 would mean the new check was never
   wired in. Clean build, on 3.11, 3.13 and 3.14.
3. **The section-order test fails when a section is moved.** Verified by moving one and
   watching it go red, not by watching it pass.
4. **`install` still works against the real PC**, and `--selftest` passes there.
5. **A five-minute live smoke after merge**: connect, text each way, an image each way, one
   reconnect resolving `doNothing`. This is the only check that covers initialisation order
   and startup timing, which no test reaches.
6. **No new orphaned processes** after the smoke — the check that caught the v3 leak.

Note for whoever runs items 4-6: **a locked PC cannot serve its clipboard**, so `wl-paste`
hangs and every one of them fails for a reason that has nothing to do with this release.
Unlock the session first and run them before it locks itself again.
