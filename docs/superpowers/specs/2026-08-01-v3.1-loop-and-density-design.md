# clipwire v3.1 — the two halves finally meet, and a retina screenshot stops doubling

**Date:** 2026-08-01
**Status:** batya-approved
**Amends:** [2026-07-31-protocol-v3-images-design.md](2026-07-31-protocol-v3-images-design.md).
Nothing on the wire changes. The persistent store gains an optional field.

## Why this exists

**Every defect this project ever shipped was found by running it, never by a test.** The
whitespace trim, GPaste's image re-encode, the leaked `gdbus` child, the safety net declaring
a healthy source dead, the retina doubling — all of them surfaced on the owner's machines,
because the Swift and Python halves have **never once executed against each other**. Each
suite drives its own side against scripted pipes. A local pairing harness was recommended
after v2 and declined twice; both times correctly, because a feature was ahead of it. Nothing
is ahead of it now.

**And there is one open user-visible bug.** A retina screenshot copied on the Mac comes back
from the PC without its pixel density and pastes at double size. Measured end to end:

| | bytes | pixels | displays at |
|---|---|---|---|
| Mac, its own retina screenshot | 259 | 100×100 | 50×50 — correct |
| PC after GPaste re-encodes | 632 | — | `pHYs` chunk gone |
| Mac, after one reconnect | 632 | 100×100 | **100×100 — double size** |

These two are one release because the fix is **a round-trip property**, and the harness is
the only thing that can evidence a round-trip property. Verifying it by hand on a machine
that locks itself after an hour is how the bug got here.

## Part 1 — the harness, and it goes first

### Substitute the command, not the transport

`Channel` spawns `/usr/bin/ssh` with `sshArguments(for:host:)` (`Channel.swift:162-163`).
The harness makes the **executable path and argv** injectable, defaulting to exactly what is
there now, and injects only from the test target.

**Not an env var.** An override read from the environment would put "exec an arbitrary
command" into a tool that lives beside the owner's ssh keys, in a public repository — a
permanent surface to document and defend, bought for a testing convenience.

**Not a mock.** Substituting `Channel`'s pipes for a fake would test a drawing of the
transport rather than the transport. Injecting argv keeps the **real** spawn, the **real**
pipes, real EOF and real `SIGPIPE` — everything this channel has actually been bitten by. The
only thing left uncovered is `sshArguments` itself, a pure function from config to strings,
and a unit test pins it.

### What the harness runs

The Swift side spawns `python3 agent/clipwire-agent.py` directly, with a fake `wl-copy` and
`wl-paste` ahead of it on `PATH`, and a fake pasteboard on the Swift side. Then a real clip
crosses a real pipe between two real implementations, for the first time in this project.

**The fake clipboard must be able to lie the way the real one does.** GPaste substitutes
bytes — measured, 105,700 in and 180,287 out — and that substitution is the direct cause of
the bug Part 2 fixes. A fake that returns what it was given cannot reproduce it, so the fake
takes a mode: return the bytes written, or return a *different* encoding of them.

### The event path must not be dead in the harness

Fake `wl-copy`/`wl-paste` on `PATH` exercise only the **polling** branch. The pump, the
worker and the safety net — where v3's two production defects actually lived — would never
run. A harness blind to precisely the class it exists to catch is worth much less than it
looks.

So the harness also carries a fake event source. Three things make it real enough, and
without any one of them the harness quietly tests nothing:

**It must answer the availability probe, not only `monitor`.** Before subscribing, the agent
runs `gdbus introspect` (`agent/clipwire-agent.py:3007`) and returns `False` on `OSError` —
which is exactly what a Mac gives, having no `gdbus` at all. A fake that serves only `monitor`
therefore leaves `available()` false, `make_watcher` falls back to the plain poller, and every
harness run **passes while exercising the polling branch only**: the precise blindness the
fake exists to remove. So the fake stands in for both subcommands, and — per the precondition
rule — the harness asserts from the agent's own log that it is on the event path, and
**aborts** if it is not.

**It must fire on any change, not only on the agent's own writes.** "An `Update` per fake
`wl-copy` write" covers one scenario: the agent applying an incoming clip. The direct PC→Mac
flow — a person copying on the PC — has no such write and would not exist in the harness at
all. So the fake clipboard is shared state that either side can change, an `Update` follows
**any** change by anyone, and the test can act as the user. The line is byte-exact to
production, taken from the real logs: `('REPLACE', 'ALL', uint64 0)` — the pump's parser
expects nothing else.

**It must flush every line.** Block-buffered output would delay lines past the pump, and the
safety net would announce a dead source — from buffering, inside the harness, with no defect
anywhere. That is the same artefact class that earned this release its precondition rule.

**If all this proves harder than a day's work, it is deferred with the reason written down and
the harness's blindness stated in the release notes — not dropped quietly.**

Two extensions are explicitly *not* required for the gate, and may be deferred with a note: a
spontaneous `Update` carrying no content change (the class that produced `_last_seen`), and a
*delayed* substitution mode, since GPaste's real takeover is seconds rather than instant and
an instant swap never exercises the read-back timing branch.

### The harness checks its own preconditions and refuses

An experiment that runs in the wrong state and reports anyway is worse than one that fails:
this release's own pipe-write measurement did exactly that, and would have reached the right
conclusion from invalid evidence. So the harness asserts its world before it tests anything —
the fakes are the ones on `PATH`, the agent is the one in this tree, the event source is
alive — and **aborts** rather than degrading to a weaker run.

## Part 2 — the density fix, after the harness proves itself

### What actually happens

The Mac sends a retina PNG. The PC applies it; GPaste takes over the selection and re-encodes
it, dropping `pHYs`. The PC hashes **what it read back** — correctly, that rule is not in
question — so the PC now holds a different hash with a later timestamp, wins the next
reconnect, and hands the Mac back a copy of its own screenshot with the density gone.

### The fix, and the mine in the obvious version

On receiving an image, if the local pasteboard already holds one that decodes to **identical
pixels**, keep the local bytes — which carry the metadata — and adopt the peer's hash.

**"Identical pixels" is defined operationally, and the obvious definition is wrong.** It means
byte equality of the two RGBA buffers after decoding both PNGs into one fixed layout, with each
image **re-tagged** as sRGB rather than converted into it.

The first draft of this design said "one colour space", and that shipped a comparison which was
inert on the machine it was written for. GPaste drops the ICC profile with the same motion that
drops `pHYs`, so a profile difference is part of the **firing condition** — present exactly when
the fix is needed. Converting both into sRGB then reports "different" for every real screenshot:
measured on the owner's Mac, 12,530 of 76,800 bytes, **max delta 2** — rounding, not a picture.

The question is not "are these the same picture" but **"is the peer's version derived from
mine"**. Equal samples are the evidence of derivation; the profile is then not a difference to
see past but the thing being rescued. Keeping the local bytes is right because they are the
original, not because the two are interchangeable.

**One premise is unmeasured and the release measures it rather than waiting.** Whether the real
GPaste leaves samples alone is unknown — the harness's fake preserves them by construction, and
the only real observation is 105,700 → 180,287 bytes, which proves different filtering and says
nothing about samples. The mismatch path logs how many bytes differed and by how much, so the
first real reconnect settles it. Failure is safe: any uncertainty already means "not identical",
which is today's behaviour. If samples do move, no pixel comparison can work, and the answer is
provenance — the PC announcing the hash it was **given** beside the hash it read back.

The obvious way to do that breaks the read-back invariant: the store would no longer describe
what the clipboard returns, so the next startup seed sees a mismatch, stamps `now`, and logs a
false `clipboard changed while apart` — exactly the defect v3 closed.

So the store keeps **two** hashes: the canonical one it announces, and the local one it
compares against its own clipboard at startup.

### The store stops being the wire type

`ClipState` is currently used for both (`Freshness.decodePayload` and `ClipStateStore.load()`
decode the same type). Adding a field to it would put a Mac-internal detail into the protocol
— and both sides tolerate unknown fields, so it would travel silently rather than fail loudly.

The store gets **its own record type** wrapping `ClipState` plus an optional local hash. They
are different contracts with different lifetimes: the store outlives agent versions on one
machine, the wire is what two machines agree on in a moment. Their being one type today is an
accident of early work, and it just came within one review of leaking.

- **The local hash is optional**, and absent means today's behaviour. An existing store file
  migrates for free.
- **The wrapper carries a comment naming this incident** — store and wire are separate on
  purpose. Without it the next tidying pass collapses them back. An optional field that never
  appears on the wire is harder to collapse by construction, which is the point.

### Only the Mac can do this

Comparing pixels needs a real PNG decoder. The Mac has one; the PC would need to implement
PNG filtering by hand, and its clipboard will carry no `pHYs` regardless because GPaste
re-encodes whatever it is handed. The fix lives on the Mac entirely.

## Order, and the gate between the parts

**Part 1 completes and demonstrates a text and an image round trip before any Part 2 task
starts.** If the harness runs late, the density fix waits rather than proceeding beside it.
Two novel things on one unclosed front is this project's signature failure shape, and it has
produced three of its production defects.

## Acceptance

1. **The harness runs both implementations against each other in CI**, and a text clip and an
   image clip each cross it. **It runs on a macOS runner** — the Swift half links AppKit and
   does not build on Linux. The existing Python matrix stays exactly where it is.
2. **The harness reproduces the re-encode.** With the fake clipboard in substituting mode, the
   loop shows the same convergence the real machines show: one frame back on the first
   reconnect, `doNothing` after.
3. **The harness fails when it should.** Break the freshness rule deliberately and watch it go
   red. A harness only ever seen passing is not evidence.
4. **The event path is live in the harness** — the fake source drives the pump, and the safety
   net does not declare it dead. Or, if deferred, the reason is written down and the blindness
   is in the release notes.
5. **A retina screenshot survives the round trip at its original display size**, measured on
   the real machines the way the failure was measured: pixels, bytes, and `NSImage.size`.
6. **No false `clipboard changed while apart`** on any reconnect after the fix — the mine the
   two-hash store exists to avoid.
7. **An existing store file still loads**, without the new field.
