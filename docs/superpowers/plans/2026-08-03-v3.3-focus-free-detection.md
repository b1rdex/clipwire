# v3.3 Focus-Free Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the PC agent's change-detection loop from stealing keyboard focus, and stop it from
declaring a healthy GPaste dead when GPaste re-offers its own clipboard content.

**Architecture:** Two tiers. The **fast tier** asks GPaste for the uuid of its top history entry
over D-Bus (**no focus** — ~103 ms, the same as the probe it replaces; the "3–5 ms" this line
carried until 2026-08-04 was the round trip, not the `gdbus` invocation, see spec §1's correction)
every few seconds. The **slow tier** keeps today's
`wl-paste --list-types` probe, but rarely and gated, as the only thing that can see "GPaste stopped
tracking the clipboard". Each tier has its own verdict rule, because their inputs have opposite
properties. Reads of actual clipboard content stay on `wl-paste`, unchanged.

**Tech Stack:** Python 3.11+ (single-file agent, stdlib only, no new dependencies), `gdbus` CLI,
Swift 5 test harness, `unittest`, XCTest.

**Spec:** `docs/superpowers/specs/2026-08-03-v3.3-focus-free-detection-design.md` — batya-approved.
Read §4.0 and §4.0.1 before Task 4; they define the machine every later task implements.

> **Every per-call latency figure written into this plan before 2026-08-04 is retracted.** Measured
> on the target machine, timed as the agent actually calls (`gdbus` as a subprocess), every
> invocation costs ~103 ms regardless of method — `Peer.Ping`, which does no work at all, costs as
> much as `GetElementAtIndex`, while the process-spawn floor is 1–2 ms. That figure is `gdbus`'s own
> startup and the round trip is lost in its noise. Spec §1 carries the full table.
>
> Affected here and **not** individually rewritten, because the shipped code is now the truth and a
> plan snippet that drifts is worse than one that admits it: the `FAST_TIER_SECONDS` comment quoted
> at ~line 597, the "three orders of magnitude above the call's 3-5 ms cost" at ~line 794 (**false**
> — 5 s / 103 ms is under two orders), and `PowerSaveMode`'s "4–5 ms" at ~lines 46 and 1466, which
> was taken the same way and is subject to the same correction. Task 12's implementer corrected all
> of these **in `agent/clipwire-agent.py`**; read the source, not these snippets.
>
> The release is unaffected in substance. The uuid tier was never worth adopting because it was
> fast — it is within a millisecond of the probe it replaces. It is worth adopting because it takes
> no focus, which is what this plan is named for.

## Global Constraints

- **The agent is one file with no dependencies beyond the stdlib.** `agent/clipwire-agent.py`.
  No pip, no apt, no new binary requirements. `gdbus` is already required and already probed by
  `GPasteWatcher.available()`.
- **Reads of clipboard content stay on `wl-paste`.** Spec §7. Nothing in this plan may fetch clip
  bodies from GPaste.
- **The probe payload never reaches a log line.** Spec §5.2. `GetElementAtIndex` returns
  `(uuid, text)`; only the uuid may be retained, and never logged either.
- **The standalone `PollingWatcher` path is untouched.** Spec §2. A machine with no GPaste keeps
  today's behaviour exactly. Everything here lives in the `GPasteWatcher` branch.
- **Both suites must stay green at every commit:** `swift test` (278 tests),
  `python3 -m unittest discover -s agent/tests` (356), `python3 Tests/fakes/test_fakes.py` (29).
- **Hash the bytes you read back, never the bytes you wrote.** Unchanged project rule; no task here
  touches content hashing, and any task that appears to needs to stop and ask.
- **Verify a check by breaking it.** Every task's final step deletes the implementation line and
  confirms the new test goes red. A test only ever seen passing is not evidence.

## Implementation note: the "monitor is on" gate

Spec §4.2 requires the slow tier to be gated on the monitor being on, so a tick cannot be a
guaranteed 3 s timeout into nothing. **The spec does not name the mechanism, and the obvious
candidate was measured and rejected during planning.**

`org.gnome.Mutter.DisplayConfig`'s `PowerSaveMode` property answers in 4–5 ms with no focus and
returned `0` with the monitor on. But **the monitor-off reading was never measured**, and the
spec's own mechanism for the hang (§1.4) is a *hotplug disconnect*, not DPMS — under which
`PowerSaveMode` may well stay `0` while the output list changes instead. Planning against an
unmeasured branch of an API is what this project keeps getting burned by.

**So the gate is implemented as the timeout itself, observed directly:** a slow-tier probe that
times out backs the slow tier off (Task 8). This is strictly better than the proxy — it needs no
new API, it has no unmeasured branch, and it covers *every* cause of a hanging `wl-paste`
including a locked session, which `PowerSaveMode` would miss entirely.

The `IdleMonitor` gate is unaffected: `GetIdletime` was measured working (Task 6).

`PowerSaveMode`'s monitor-off reading goes on the hardware-acceptance list (Task 11) so a future
cycle can adopt it as a cheap early exit if it turns out to be truthful.

```python
def history_uuid(state):
    """The uuid of the top history entry.

    Derived from `generation` -- which set_body() stamps on every WRITE -- and
    NOT from the whole state file, so a harness (or the substitution path) that
    rewrites `types` without making a new entry leaves this alone. That is the
    property the v3.3 fast tier rests on, so the fake must have it too: GPaste's
    re-offer of its own content changes the offered types and adds no history
    entry.

    A harness that wants to move the uuid without touching `generation` -- an
    entry deleted from the GPaste UI, say -- sets `history_uuid` explicitly.
    """
    explicit = state.get("history_uuid")
    if explicit:
        return str(explicit)
    digest = hashlib.sha256(("gpaste-history-%s" % state.get("generation", "0"))
                            .encode("utf-8")).hexdigest()
    return "%s-%s-%s-%s-%s" % (digest[0:8], digest[8:12], digest[12:16],
                               digest[16:20], digest[20:32])


def call_get_element_at_index(path):
    """`GetElementAtIndex(0)` -- (uuid, text) for the top of history.

    The text is deliberately included and deliberately NOT what the agent is
    allowed to use: the real method returns it, so a fake that omitted it would
    let a payload-logging regression pass unseen (spec 5.2).
    """
    state = fake.load(path)
    body = fake.body_bytes(state)
    text = body.decode("utf-8", "replace")[:40] if body else ""
    say("('%s', '%s')" % (history_uuid(state), text.replace("'", "")))
    fake.note(PROGRAM, "call GetElementAtIndex(0) -> uuid")
    return 0
```

```python
def start_gdbus_monitor(self):
    process = subprocess.Popen(
        [sys.executable, os.path.join(FAKES, "gdbus"), "monitor", "--session",
         "--dest", "org.gnome.GPaste", "--object-path", "/org/gnome/GPaste"],
        stdout=subprocess.PIPE, stderr=subprocess.DEVNULL, text=True,
        env=dict(os.environ, CLIPWIRE_FAKE_CLIPBOARD_STATE=self.state))
    self.addCleanup(process.terminate)
    os.set_blocking(process.stdout.fileno(), False)
    time.sleep(0.2)                       # let it take its baseline digest
    process.stdout.read()                 # discard the "Monitoring signals" banner
    return process

def drain(self, process, seconds):
    """Every Update line the monitor emitted within `seconds`."""
    time.sleep(seconds)
    text = process.stdout.read() or ""
    return [line for line in text.splitlines() if "Update" in line]
```

```python
def _env_seconds(name, default):
    """An interval overridden from the environment, or `default`.

    Exists for PairingHarness, which needs sub-second tiers to exercise in
    seconds what production does in minutes. Production sets none of these, so
    the constants below are what a real agent runs.

    Anything unparseable or non-positive returns the default rather than
    raising: a typo in a harness must not produce a zero-second poll that spins
    a core, and must not take down an agent on a machine where the variable was
    never meant to be read.
    """
    raw = os.environ.get(name)
    if not raw:
        return default
    try:
        value = float(raw)
    except ValueError:
        return default
    return value if value > 0 else default
```

**Context:** spec §4.0.1 is the blocker batya caught. `frozen` must mean *the call succeeded and

- [ ] **Step 1: Write the failing test**

```python
class TestHistoryUuidProbe(unittest.TestCase):
    def probe(self, stdout=b"", returncode=0, raises=None):
        def run(argv, **kwargs):
            if raises is not None:
                raise raises
            return subprocess.CompletedProcess(argv, returncode, stdout, b"")
        return agent.gpaste_history_uuid(run=run)

    def test_parses_the_uuid_from_a_real_shaped_reply(self):
        self.assertEqual(
            self.probe(b"('ecf318fd-a295-40a8-b591-9721fcf7cbcc', 'CD-3167')\n"),
            "ecf318fd-a295-40a8-b591-9721fcf7cbcc")

    def test_a_nonzero_exit_is_not_measured(self):
        self.assertIsNone(self.probe(b"", returncode=1))

    def test_a_timeout_is_not_measured(self):
        self.assertIsNone(self.probe(
            raises=subprocess.TimeoutExpired(["gdbus"], 3)))

    def test_a_missing_gdbus_is_not_measured(self):
        self.assertIsNone(self.probe(raises=FileNotFoundError()))

    def test_unparseable_output_is_not_measured(self):
        """A renamed method or a changed reply shape must read as 'unknown',
        never as a uuid and never as a crash -- spec 4.0.1."""
        for junk in (b"", b"()\n", b"no quotes here\n", b"(uint64 0,)\n"):
            self.assertIsNone(self.probe(junk), "%r parsed as a uuid" % junk)

    def test_the_payload_never_reaches_the_return_value(self):
```

## The prose-verification instrument this run built

Five passes, developed over five fix rounds of the documentation audit. **Every clause was added by
a round that had been bitten for omitting it**, which is why it is recorded in full rather than
summarised. It exists in no other tracked document.

> **extract token → NORMALISE WHITESPACE → grep ACROSS ALL ARTEFACTS AND ALL CYCLES** (source,
> tests, README, plan, this cycle's ledger *and previous cycles'*, plus the audit's own report)
> **→ classify each hit by what it renders → prefer the LATEST attribution where the record
> supersedes itself → check every hit in the relevant class — run by whoever makes the claim OR
> THE FINDING.**

| pass | catches | blind to |
|---|---|---|
| by-file sweep (text against code) | stale neighbours | the edit itself |
| paragraph against itself | internal miscounts | claims that are consistent and wrong |
| claim against its cited source | citing a spec that says the reverse; borrowing a number from an adjacent table | claims citing nothing |
| referent grep **+ classify by what each hit renders** | completeness claims over a named symbol | populations with no shared token; **and a complete grep sorted wrong** |
| **run every pass on the FINDING, not only on the claim** | a finding of the form "the record does not contain X", which is itself a claim about a population | a finding that asserts nothing about the record |

**Why each clause is there:**

- **Normalise whitespace** — `grep` is line-oriented and prose wraps; a line-based pass missed a hit
  a normalised one found.
- **All artefacts** — two fixes landed in the source and left the README and the audit's own report
  asserting the old claim. A fix that touches *one* artefact leaves every other one stale, and
  nothing announces it.
- **All cycles** — cost two rounds of invented and then over-hedged provenance. The fact that
  settled it was in the *previous* cycle's `progress.md` the whole time.
- **Classify by what each hit renders** — the grep is mechanical; the **sort** is a judgement, and
  the sort is where it goes wrong even when the grep is complete.
- **Prefer the latest attribution** — one figure's cause had been re-attributed three times and the
  middle version was cited as current.
- **Run it on the finding** — three consecutive rounds turned on a *finding* being wrong. "The
  record does not contain X" is itself a claim about a population and needs the same grep.

**The blind spot, named so nobody treats the instrument as sufficient:** it cannot see a
completeness claim whose population has **no shared token**. "The one place in this file where an
observation is asked for without the token having moved" quantifies over a *behaviour*, and no grep
finds the counterexamples. That class needs the population named explicitly and swept by
claim-shape — or the uniqueness claim replaced by a rule, which is what the audit did.

**The writing-side rule that makes it cheap:** *a sentence whose subject is a set has created a grep
obligation — write the grep into the prose and state its result.* That turns an assertion a future
reader must trust into a check they can re-run.

**And the honest summary of what five rounds cost:** the passes were never the hard part. The hard
part is that **each one has to be run against the artefact you just produced**, and the impulse
after writing a repair is to verify the thing you repaired rather than the repair itself. Every
round failed exactly there, in a different place, and the instrument grew a clause each time.
Corollary the run also earned: **"I have nothing to dispute" is itself a signal** — the one round
that produced no correction is the round that filled a gap with invention rather than naming it.
