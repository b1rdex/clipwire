# v3.2 implementation plan — provenance

(batya-approved). Read it first; this plan does not restate its reasoning.

Baselines: **Swift 285**, `python3 Tests/fakes/test_fakes.py` **29**,
`python3 -m unittest discover -s agent/tests` **317**. All green.

## The one thing that must not move

`fixtures/freshness.json` has not changed since the v2 commit — it survived v3, v3.0.1 and
v3.1 untouched. Provenance runs **before** that formula and must not perturb it. Any task that
finds itself editing that file has misunderstood something; stop and report.

## Task 1 — the shared rule and its fixture

One function, both languages, one golden file. Not two implementations that agree today: this
project's recorded defect shape is exactly one idea grown in two places.

- `resolve_provenance(mine, peer)` in `agent/clipwire-agent.py` beside `resolve_freshness`
  (`:331`), and `resolveProvenance(mine:peer:)` in `Sources/clipwire/Freshness.swift` beside
  `resolveFreshness` (`:182`).
- It answers one question: **is either side's content descended from the other's?** True when
  `peer.origin == mine.sha256`, or when `mine.origin == peer.sha256`.
- **Equality counts only between two values that are both present.** `None == None` is `True`
  in Python and `nil == nil` is `true` for a Swift `Optional`; the naive form therefore fires
  on an empty clipboard against a peer with no origin, which is a locked PC against an ordinary
  Mac, and it would kill the `(_, nil) → sendMine` recovery for **every** kind of content.
- `fixtures/provenance.json`, beside `freshness.json`, read by both suites — copy the shape of
  `agent/tests/test_freshness.py` and `Tests/clipwireTests/FreshnessTests.swift`.

The fixture must include the nil cases explicitly. A table that only covers present values
would pass with the bug in it.

## Task 2 — `origin` on the wire

`encode_clip_state` (`:196`) / `decode_clip_state` (`:241`) in Python; `ClipState`
(`Sources/clipwire/Freshness.swift:29`) in Swift.

- One optional field. Absent means today's behaviour, in both directions, so a mismatched pair
  degrades rather than failing.
- **`origin` is admissible only beside a non-null `sha256`**, rejected in decode the way `kind`
  already is. `ClipState`'s custom `init(from:)` already enforces nil-iff-nil for `kind` — this
  is the same guard, and the existing one is the model to copy.
- Golden vectors in `fixtures/frames.json` for a clip-state with an origin and one without.

## Task 3 — the PC remembers what it was given

`_expect_reoffer` currently carries only the peer's timestamp:
`self._expect_reoffer = ts if kind == KIND_IMAGE else None` (`agent/clipwire-agent.py:1237`).
Widen it to carry the hash too. **The hash is already in scope one line above**, where
`_last_seen` is set from the same write — the bytes the PC writes are the bytes the Mac hashed
and sent, so their digest *is* the peer's canonical hash.

Then, in `_consume_image_reoffer` (`:1550`): on the branch that consumes the expectation — the
first of its three `True` branches, and **only** that one — record the origin alongside the
re-encode's hash.

Read that docstring before touching it. It already explains why the other two branches return
`True` without consuming, and getting that distinction wrong is how a user's own copy gets
labelled a derivative and silently never syncs.

## Task 4 — the origin's life in the store

The agent dies with every connection; `sshd` starts a fresh one. So the process that recorded
an origin **is already dead** at the announce that needs it, and a field living only in memory
is worth nothing here.

- The persistent store becomes `(sha256, ts, kind, origin)` — `save_clip_state` (`:1920`) and
  `load_clip_state` (`:1858`) carry it.
- **`resolve_startup_state` (`:1944`) returns the stored record WHOLE on its match branch.**
  Rebuilding it around the current hash drops the origin and the fix dies on the *second*
  reconnect — which is precisely what the harness's two-reconnect test exists to catch.
- Its **changed** branch clears the origin, and every store write outside task 3's recording
  branch writes `origin=None`. A stale origin is not harmless: the PC holding new content with
  an origin the Mac still matches means the PC **never sends it**.
- A store file with no `origin` key loads as `origin=None`. `TestV2StoreIsRejected`
  (`agent/tests/test_clip_state_store.py:710`) is the precedent for a missing key; follow it.

Note this is the same preserve-on-match / drop-on-change pair task 6 deletes from the Mac. It
was never wrong — it was on the wrong side of the wire.

## Task 5 — disarm by observation, never by a clock

The expectation must not stay armed forever on a machine with no GPaste, or a user's next image
copy is absorbed as though it were the re-offer — and with an origin stamped on it that clip is
now lost **permanently** rather than arriving one connection late.

**Do not implement this as a timer.** Two mines, both in the phrase "30 seconds":

- The takeover is measured at 1–4 s, but that is when the substitution *happens*. The window
  must cover when it is **observed**, and with the event source dead only the safety-net poll
  sees it, up to a full interval later. A wall-clock deadline races the tick carrying the
  observation, and the phase decides: 29.9 s absorbs correctly, 30.1 s ships the degraded copy
  live with no origin recorded.
- After the two-tick verdict the poll runs at **1 second**, shorter than the takeover, so a
  window meaning "the current interval" would disarm deterministically before the re-offer.

Instead, one read decides both outcomes, in the poll's no-change branch (`_observe_tick`,
`:2859`):

- **bytes differ from `_last_seen`** → the re-offer, consume it whatever the clock says
- **bytes are the ones we wrote**, and at least `SAFETY_NET_POLL_SECONDS` (`:2581`, a constant,
  never the interval in force) has passed since the write → no GPaste here, disarm

The branches are mutually exclusive **by content**, so no ordering remains to race.

**Health accounting outranks absorption.** A re-offer observed by a signal-less poll must count
toward the two-tick dead-source verdict **before** it is absorbed, or a dead extension whose
first unsignalled change happens to be a re-offer stays undiagnosed until the next change.

## Task 6 — remove what provenance replaces

- `StoredClipState.localSHA256` and everything reading it. The Mac stops adopting the peer's
  hash; the `sendMine` verification returns to comparing `mine.sha256`.
- `Sources/clipwire/ImagePixels.swift` entirely, and the `.imageClip` branch that called it.

**The removal is free of migration**: v3.1's fix never fired on any real machine, so no store
anywhere carries `localSHA256`.

When deleting a test, be sure it was pinning the removed mechanism rather than pinning a
behaviour that still matters. Report each one and which it was.

## Task 7 — prove it

- In the harness, using the fake that now moves every pixel sample: a screenshot Mac→PC, two
  reconnects, `doNothing` both sides, **no frame in either direction**, and the Mac still
  holding its original bytes.
- The nil case: an empty clipboard against a peer with no origin still recovers via `sendMine`.
- The persistence case: an origin recorded, the agent restarted, and suppression still working
  on the **second** reconnect.
- The stale case: new content on the PC with the Mac holding the ancestor is still sent.
- The phase case: with the event source dead, a re-offer first observed by the tick *after* the
  threshold is consumed rather than disarmed.

Then on the real machines: `pixelsWide`/`pixelsHigh` against `NSImage.size`, before and after a
reconnect. **The PC must be unlocked** — a locked session makes every read hang, which is
settled and documented and not a fault to re-diagnose.

## Standing instructions for every task

- **Check every identifier and line number against the real file** before relying on it. v3's
  briefs contained 53 wrong symbols; later branches caught four more, and every time the line
  numbers around the wrong symbol were correct — which is exactly why nobody checked it.
- **Build what the brief says.** If you disagree, do it as specified and report the
  disagreement separately rather than acting on it.
- **Verify a check by breaking it**, not by watching it pass.
