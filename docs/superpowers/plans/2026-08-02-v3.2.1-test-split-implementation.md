# v3.2.1 Test-Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the three largest test files into anchors plus shards, changing no production
code, and prove by four independent mechanical checks that not one test was lost, weakened or
silently skipped.

**Architecture:** Each original file is partitioned into intervals. Every new file is
`declared scaffold + a list of intervals`, and a manifest asserts the intervals are disjoint,
cover `[1, N]`, and concatenate byte-for-byte back to the committed blob. Swift shards are
`extension HandleFrameTests { … }` so the `(class, method)` pairs survive; Python shards are
`test_watcher_<subject>.py` importing shared constants from their anchor.

**Tech Stack:** Swift 6 / SwiftPM / XCTest on macOS; Python 3.11+ / `unittest`; `git`; the
existing `scripts/comment_only.py` as the precedent for a committed, auditable checker.

**Spec:** `docs/superpowers/specs/2026-08-02-v3.2.1-test-split-design.md` (batya-approved). Read
it before starting. The reasoning behind every rule below lives there, and several rules look
arbitrary until you know what they were weighed against.

## Global Constraints

Every task's requirements implicitly include this section.

- **Frozen paths — not one byte may change across the whole branch:** `Sources/**`,
  `agent/clipwire-agent.py`, `Package.swift`, `fixtures/**`, `Tests/fakes/**`.
  Check: `git diff --stat main...HEAD -- Sources/ agent/clipwire-agent.py Package.swift fixtures/ Tests/fakes/`
  must print nothing.
- **Baselines are derived, never typed:** Swift 278 pairs, Python 356 pairs, fakes 29 tests are
  what today's tree produces, but every check computes them from a `git worktree` at the
  merge-base.
- **Green means `failures=0 errors=0 skipped=0`,** stated explicitly, not "the suite passed".
- **The commit chain is fixed:**
  `merge-base → C1 comment debts → C2 widening → C3 Pairing → C4 test_watcher → C5 HandleFrame`.
  After a file's split commit, that file is never edited again on this branch.
- **The widening budget is exactly 9 lines**, listed in Task 3. Removal-only. No `internal` is
  ever written in — it is the default and stays unspelled.
- **No new abstractions.** No shared fakes file, no helper consolidation, no "while we are here",
  no reordering within an interval. The only permitted new lines are the declared scaffold.
- **Never `git commit --amend`** — another agent may share this tree. Use
  `git commit -- <explicit paths>`.
- **The repo is public.** Grep every diff for anything tying it to the owner's work accounts
  before any push. Prose counts — that is where it slipped through before.

The `agent_under_test` block is copied **verbatim and identically** into every shard rather than
trimmed per shard. Identical scaffold is mechanically checkable; a per-shard subset is a judgement

there is no linter in CI.

**Never `from test_watcher import *`.** A star import pulls the anchor's `TestCase` subclasses
into the shard's namespace and `unittest` discovers and runs them twice, inflating the multiset
that leg 2 checks.

### Task 1: The verifier, built and broken before anything is split

**Files:**
- Create: `scripts/split_manifest.py`
- Create: `scripts/test_pairs.py`
- Create: `.superpowers/sdd/2026-08-02-v3.2.1-test-split/manifests/` (gitignored scratch for
  hand-checking; the real manifests are committed beside each split)

**Interfaces:**
- Produces: `scripts/split_manifest.py verify <manifest.json>` → exit 0/1 and a report;
  `scripts/test_pairs.py baseline <rev>` → sorted `Class.method` lines on stdout;
  `scripts/test_pairs.py compare <rev>` → exit 0/1.
- A manifest is JSON: `{"original": "<path>", "blob": "<rev>", "files": [{"path": …,
  "scaffold_before": [<line strings>], "scaffold_after": [<line strings>],
  "intervals": [[start, end], …]}]}`. Two scaffold lists rather than one, because a Swift shard
  needs a trailing `}` to close its extension and a Python shard needs nothing after its spans.

- [ ] **Step 1: Write `scripts/test_pairs.py`**

Two subcommands. `baseline <rev>` creates a detached worktree at `<rev>` under
`$TMPDIR`, runs both suites there, and prints the sorted `(class, method)` pairs, one per line,
prefixed `swift ` or `python `. `compare <rev>` does that and diffs against the working tree's.

Pairs must come from the runners, never from a grep:

```python
# python: enumerate through unittest's OWN loader, in a subprocess rooted at
# agent/tests. This IS discover's mechanism -- not a grep of the sources -- so
# it still cannot miss a module that stopped being importable.
ENUMERATE = r"""
import unittest, json
out = []
def walk(s):
    for t in s:
        walk(t) if isinstance(t, unittest.TestSuite) else out.append(t.id())
walk(unittest.TestLoader().discover("."))
# keep Class.method, drop the module: a split changes the module by design.
print(json.dumps(sorted(".".join(i.split(".")[-2:]) for i in out)))
"""
def python_pairs(root):
    r = subprocess.run([sys.executable, "-c", ENUMERATE],
                       cwd=os.path.join(root, "agent/tests"),
                       capture_output=True, text=True)
    if r.returncode != 0:
        fail(f"could not enumerate python tests:\n{r.stderr[-2000:]}")
    return ["python " + p for p in json.loads(r.stdout)]

# swift: `swift test list` prints clipwireTests.Class/method
def swift_pairs(root):
    r = subprocess.run(["swift", "test", "list"], cwd=root,
                       capture_output=True, text=True)
    return sorted("swift " + l.split(".", 1)[1].replace("/", ".")
                  for l in r.stdout.splitlines()
                  if l.startswith("clipwireTests."))
```

**Do not parse `unittest -v` output.** The suites write agent log lines (`reconciled with the
peer: …`, `clipboard changed while apart`) onto the same streams, and one landing mid-record
corrupts a regex parse **silently** — a confident wrong number, which is this project's most
frequent failure mode. The loader walk fails loudly instead.

`swift test list` was measured directly against an extension-declared test and does list it under
the original class name (278 → 279 with a one-method probe in place). That was checked with a
probe rather than assumed, because the whole Swift half of leg 2 rests on it and the earlier
extension probe only established that such methods *execute* — a different instrument.

The comparison is a **multiset** — compare sorted lists, not sets, so a duplicate cannot cancel a
loss. `failures/errors/skipped` come from a real run of both suites, since enumeration alone
cannot tell an executed test from a skipped one.

- [ ] **Step 2: Write `scripts/split_manifest.py`**

```python
def verify(manifest):
    # splitlines(), NOT split("\n"): a file ending in a newline gives split()
    # one extra empty element, so n would be 1540/2166/3969 and the totality
    # check would reject a CORRECT manifest. The interval maps in this plan
    # were computed with splitlines() and the checker must agree with them.
    original = git_show(manifest["blob"], manifest["original"]).splitlines()
    n = len(original)
    spans = [(s, e, f["path"]) for f in manifest["files"] for s, e in f["intervals"]]
    # 1. disjoint and total
    covered = sorted(spans)
    expect = 1
    for s, e, _ in covered:
        if s != expect:
            fail(f"gap or overlap at line {expect}: next interval starts {s}")
        expect = e + 1
    if expect != n + 1:
        fail(f"intervals cover {expect - 1} lines, file has {n}")
    # 2. byte-identical reconstruction, in ORIGINAL order
    rebuilt = b"\n".join(l for s, e, _ in covered for l in original[s - 1:e])
    if sha256(rebuilt) != sha256(git_show(manifest["blob"], manifest["original"])):
        fail("reconstruction differs from the committed blob")
    # 3. every produced file is scaffold + its intervals, exactly
    for f in manifest["files"]:
        want = f["scaffold_before"] + [l for s, e in f["intervals"]
                                       for l in original[s - 1:e]] + f["scaffold_after"]
        if read_working(f["path"]) != want:
            fail(f"{f['path']} is not scaffold + its declared intervals")
```

**Read the original from `git show <blob>`, never from the working copy** — v3.0.1's task 3
strengthened the proof exactly this way, and it makes the check independent of whatever produced
the files.

- [ ] **Step 3: Break the manifest checker four ways and watch each one red**

A checker only ever seen passing is not evidence. On a scratch copy, confirm it reports a
*specific, correct* failure for each:

1. **A dropped line** — delete one line from a produced file. Must fail **check 3**.
2. **A gap** — change an interval from `[64,527]` to `[64,526]`. Must fail **check 1**, naming 527.
3. **An overlap** — change `[528,638]` to `[527,638]`. Must fail **check 1**, naming 527.
4. **A reordered pair of intervals** inside one file. Must fail **check 3** even though the line
   multiset is unchanged.
5. **A blob whose bytes do not reassemble** — e.g. a file containing a CRLF line, with an
   interval list that drops a byte. Must fail **check 2**.

**Control 5 exists because the first four never reach check 2, the byte-identity comparison this
tool is named for.** Checks 1 and 3 absorb every mutation the obvious controls produce: check 2
never reads a produced file from disk, and its `sorted(spans)` makes one file's internal interval
order invisible to it. An earlier draft of this plan asserted that controls 1 and 4 exercised
check 2; they do not, and the release would have shipped a third of its central instrument never
once seen failing. **Confirm which check each control lands at, rather than that it failed.**

Also hand it a manifest for a file it cannot read and confirm it **refuses** rather than
reporting a confident number — v3.0.1's checker shipped three defects of exactly that shape, all
producing plausible wrong answers rather than errors.

- [ ] **Step 4: Break the pair comparator twice**

1. Delete one test method in a scratch copy → `compare` must name that exact pair as missing.
2. Add `@unittest.skip` to one test → `compare` must fail on `skipped != 0`, **not** pass because
   the pair still exists. This is the check that the skipped-count leg is real.

- [ ] **Step 5: Record the baselines the scripts derive**

Run `scripts/test_pairs.py baseline HEAD`. Confirm 278 swift + 356 python pairs. If either number
differs from this plan, **stop and report** — the plan is stale, not the tree.

- [ ] **Step 6: Commit**

```bash

git commit -m "Build the split verifier, and break it before trusting it"
```

- [ ] **Step 1: Write `scripts/modifier_only.py`**

```python
def check(a_lines, b_lines):
    if len(a_lines) != len(b_lines):
        fail(f"line count changed: {len(a_lines)} -> {len(b_lines)}")
    changed = 0
    for i, (a, b) in enumerate(zip(a_lines, b_lines), 1):
        if a == b:
            continue
        changed += 1
        stripped = a.replace("private ", "", 1) if "private " in a else \
                   a.replace("fileprivate ", "", 1)
        if b != stripped:
            fail(f"line {i} is not a bare modifier removal:\n  was {a!r}\n  now {b!r}")
    return changed
```
